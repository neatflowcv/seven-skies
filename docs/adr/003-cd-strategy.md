# ADR-003: CD (Continuous Deployment) 전략

## 상태

Accepted

## 컨텍스트

애플리케이션의 자동 배포를 위한 CD 시스템이 필요하다.
다양한 CD 도구 옵션이 존재한다:

* ArgoCD
* Flux
* Jenkins X
* Spinnaker
* 기타 GitOps 도구

배포용 매니페스트를 관리하는 전략도 필요하다:

* 애플리케이션 저장소와 동일한 저장소에 배포 매니페스트 포함
* 별도의 저장소에 배포 매니페스트 관리

## 결정

**ArgoCD를 CD 도구로 사용하고, 배포용 프로젝트는 별도 저장소로 분리한다.**

### ArgoCD 선택 이유

1. **GitOps 원칙**: Git을 단일 소스로 사용하는 GitOps 패러다임 지원
2. **선언적 배포**: Kubernetes 매니페스트를 선언적으로 관리
3. **자동 동기화**: Git 저장소 변경사항을 자동으로 감지하여 배포
4. **롤백 지원**: 이전 버전으로의 쉬운 롤백 기능
5. **멀티 클러스터**: 여러 클러스터 관리 지원
6. **UI 제공**: 웹 UI를 통한 배포 상태 모니터링

### 배포 프로젝트 분리 이유

1. **책임 분리**: 애플리케이션 코드와 인프라/배포 매니페스트의 명확한 분리
2. **접근 권한 관리**: 배포 매니페스트에 대한 접근 권한을 별도로 관리 가능
3. **독립적 버전 관리**: 배포 매니페스트의 변경 이력이 애플리케이션 코드와 독립적으로 관리
4. **재사용성**: 동일한 애플리케이션을 여러 환경에 배포할 때 배포 저장소만 분기하여 관리 가능
5. **보안**: 민감한 설정값(Secret 등)이 포함된 매니페스트를 별도로 관리하여 보안 강화

### 배포 프로세스

1. **CI 단계**: Tekton이 애플리케이션을 빌드하고 컨테이너 레지스트리에 이미지 푸시
2. **이미지 태그 업데이트**: 배포 저장소의 매니페스트에서 이미지 태그 업데이트
3. **Git 커밋**: 변경사항을 배포 저장소에 커밋 및 푸시
4. **ArgoCD 동기화**: ArgoCD가 Git 변경사항을 감지하고 자동으로 배포 실행
5. **배포 모니터링**: ArgoCD UI를 통해 배포 상태 확인

## 결과

### 긍정적 영향

* GitOps 원칙을 통한 배포 프로세스의 투명성 및 추적 가능성 향상
* 배포 매니페스트와 애플리케이션 코드의 명확한 책임 분리
* 배포 저장소의 독립적 관리로 인한 유연성 확보
* ArgoCD의 자동 동기화로 인한 배포 자동화
* UI를 통한 배포 상태 모니터링 용이

### 부정적 영향

* 두 개의 저장소 관리로 인한 복잡도 증가
* 배포 저장소와 애플리케이션 저장소 간의 동기화 필요
* ArgoCD 학습 곡선 존재
* 배포 저장소에 대한 별도의 접근 권한 관리 필요
